# 상점 거래와 마을 휴식 일관성 보완

## 변경

- 상점 휴식과 회복 NPC가 같은 마을 할인 정책을 사용한다. 상점 휴식 버튼의 표시 가격과 실제 차감 금액을 현재 복구 단계에 맞춰 갱신한다.
- `CanRestParty`, `CanBuyItem`, `CanSellItem`으로 사용 가능 조건을 공유한다. 버튼 활성화와 실제 거래 검증이 같은 기준을 사용한다.
- 수량이 `int.MaxValue`인 도구는 구매 전에 거절한다. 판매 대금을 전부 받을 수 없을 만큼 금화가 많은 경우 판매를 거절한다. 수량·재화의 상한 처리로 구매 비용이나 판매 도구만 잃지 않게 한다.
- 잘못된 도구 ID, 음수 구매 가격, 0 이하 판매 가격은 거래하지 않는다. 핵심 도구의 중복 구매와 판매 제한은 유지한다.
- 구매·판매는 도구 수량과 금화를 모두 반영한 뒤 변경 이벤트를 알린다. 기존 `TryBuyItem`, `TrySellItem`, `TryRestParty` 호출 방식은 유지한다.
- 상점이 열려 있는 정착지에서만 거래하고, 같은 프레임의 중복 거래는 막는다. 숨긴 이전 행의 입력을 받지 않고 비활성 템플릿의 버튼 리스너도 한 번만 연결한다.
- 파티 HP 및 마을 복구 단계 변화에 따라 휴식 조건과 재고를 갱신한다. 저장 객체가 바뀌면 이전 상점을 닫는다.
- 상점과 회복 NPC는 저장 실패 시 거래·회복 결과와 함께 재저장 안내를 표시한다. 실제 플레이 데이터의 변경을 취소하지는 않는다.
- 회복 NPC의 휴식도 마을 복구 활동에 반영한다. 할인액이 늘어났는데도 고정 10금화 할인으로 설명하던 문구는 실제 차감액 안내로 대체한다.

## 확인 범위

- 별도 검증 복사본에서 Unity 2022.3.62f3 컴파일 및 `ShadowTheater.EditorTools.SourceOperationBatch.RunForCi`로 Editor Play Mode 기동 확인.
- PrologueTheater에서 Player/Grid/GameFlow 초기화 성공, 12초 관찰 중 런타임 오류 0, Unity 종료 코드 0.
- 신규 한글/영문 문구의 JSON·키 중복·서식 인자, 검증 소스 일치 여부 및 기존 수정 파일 해시 확인.
- 기존 컴파일 경고는 남아 있다. 실제 구매·판매·휴식, 재화 상한 상황, 저장 실패 및 화면 표시 조작은 이번 기동 확인에 포함하지 않았다. 수동 플레이 검증은 사용자가 진행한다.
- APK/AAB 생성, 에뮬레이터 설치 및 전체 회귀 검사는 실행하지 않는다. 기존 패키지/에디터 버전 수정과 미추적 생성 파일은 보존한다.
