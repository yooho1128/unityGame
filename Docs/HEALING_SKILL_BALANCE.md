# 반복 회복 방지

자기 대상 회복 스킬(Self + healRatio > 0)은 그림자 개체마다 한 전투에 총 3회만 사용할 수 있다.
여러 회복 스킬을 보유해도 같은 횟수와 재사용 대기를 공유한다.
사용한 턴 뒤에 두 턴을 쉬어야 한다. 예를 들어 1턴에 회복했다면 2·3턴에는 회복 스킬을 사용할 수 없고 4턴부터 다시 가능하다.
FP 비용과 첫 회복량은 유지한다. 무한 회복 생존을 막는 것이 목적이며 실제 승률 재조정은 하지 않았다.

## 적용

- HealingSkillBudget은 각 BattleUnit에 소속된다. 플레이어·적·자동 전투에 동일하게 적용된다.
- 교체하거나 다른 회복 스킬을 골라도 횟수가 초기화되지 않는다. 대기는 전체 전투 턴을 기준으로 진행한다.
- 다음 전투에서 새 BattleUnit을 만들면 다시 3회가 된다. 세이브 스키마와 스킬 에셋을 변경하지 않는다.
- 만피/기절/빙결로 회복을 실행하지 못하면 횟수를 쓰지 않는다. 실제 회복 실행 시에만 횟수를 차감한다.
- AI는 횟수 소진/대기 중 회복을 후보에서 제외한다. 실행 시점에도 같은 조건을 다시 검사하고 사용할 수 없으면 기존 FP 부족 처리처럼 기본 공격으로 대체한다.
- 플레이어 스킬 선택지에 공용 남은 횟수와 대기 규칙을 표시하고, 금지 상태에서 버튼을 비활성화한다.
- 수량을 소비하는 도구 회복, 보스 페이즈 일회성 회복, 필드 회복에는 이 스킬 한도를 적용하지 않는다.
- 전투 밸런스 시뮬레이터와 브라우저 프로토타입, 웹 도감 안내도 같은 기준으로 변경한다.

## 검증

node Tools/check-healing-policy.cjs는 실제 프로토타입의 회복 판정 함수를 실행해 1/4/7턴 회복,
2턴 대기, 세 번 이후 차단, 다른 회복 스킬 우회 차단, 만피/기절 차단을 검사한다.
Unity 런타임·AI·UI·시뮬레이터 연결과 프로토타입 JS 구문도 검사한다.

HealingSkillRegression은 Unity 감사에 연결되어 실제 BattleUnit 회복량/만피 무소모,
두 스킬 간 공용 한도, AI 후보 제외, 독립 개체, 다음 전투 초기화, 아이템으로 한도 초기화 방지를 검사한다.
이 환경에서는 C# 구문 검사만 수행했다. Unity 컴파일·회귀 검사·Play Mode·수동 전투 균형은 미검증이다.
