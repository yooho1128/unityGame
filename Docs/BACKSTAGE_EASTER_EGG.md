# 장막 뒤 비밀 대기실

외부 인증 화면이나 키보드 단축키가 아니라, 실제 월드의 오브젝트 조사와 성공한 필드 아이템 사용 조합으로 여는 숨겨진 기능이다.
정식 빌드에서도 같은 조건으로 동작한다. 공개 소스의 조건을 아는 사람은 재현할 수 있으므로 소유자 인증이나 보안 경계로 취급하지 않는다.

## 구현

BackstageRitual은 조사/사용 순서와 횟수만 담당하며, BackstageEasterEgg가 지역·위치·방향과 세이브를 검사한다.
DialogueInteractable에서 대화를 끝까지 읽었을 때만 조사 횟수를 인정한다.
SaveManager.TryUseFieldItem의 성공 경로에서만 사용 횟수를 인정한다. 미리보기, 최고 레벨 사용 실패, 취소는 횟수를 늘리지 않는다.
도중에 걷거나 지역을 바꾸거나 다른 도구를 성공적으로 사용하면 조합을 초기화한다. 세이브 인스턴스 교체 시에도 진행을 버린다.

완성 후 선택지에 응답하면 해당 슬롯에 해금 플래그를 남긴다.
이후 같은 오브젝트의 같은 위치/방향에서 다시 비밀 대화를 열 수 있다. 다른 슬롯에 해금이 전파되지 않는다.
기존 DialogueController.PlayDynamic의 플레이어 잠금·터치 선택지·취소 처리를 사용한다.
대화 선택 콜백에서는 실행하지 않고 대화가 정상 완료된 뒤 실행하므로 취소/씬 전환으로 보상을 받지 않는다.
기존 대사와 메인 퀘스트 플래그는 변경하지 않는다.

## 커튼 뒤에서 가능한 일

- 소품비 10,000 금화
- 일반 소모품 각 10개: 진행용 핵심 도구와 이벤트 전용품 제외
- 파티 전원 HP 회복
- 파티 전원 5레벨 상승과 회복: 최고 레벨 상한 준수

각 실행 전에 현재 세이브를 먼저 저장한 뒤 Application.persistentDataPath/backstage-backups에 별도 JSON 복사본을 만든다.
백업이 실패하면 치트는 적용하지 않는다. 적용한 슬롯에는 developer_cheats_used 플래그를 남기고 저장한다.
적용 후 저장이 실패하면 게임 대사로 실패를 알리며 원본 별도 백업을 유지한다.

## 확인

python Tools/check-backstage-easter-egg.py는 실제 장소/아이템 훅, 이동·씬·세이브 초기화,
대화/백업/효과 적용 순서, 정식 빌드에서의 가용성을 정적으로 검사한다.
BackstageEasterEggRegression은 조사/사용 정상 조합, 부족/초과, 틀린 아이템, 초기화 회귀 사례를 Unity 감사에 연결한다.

이 환경에는 Unity가 없어 C# 구문 검사와 정적 통합 검사만 실행했다.
Unity 컴파일·Play Mode·실기기에서 조합/취소/재진입/슬롯 분리/백업 복구를 확인해야 한다.
