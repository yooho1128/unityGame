# 후반 보급 거점·그림자 관리·거래 편의

후반 거점 → 그림자 관리 → 가방/상점 편의 순서로 보강했다.
저장 형식 v14와 기존 아이템 ID·효과·단가·경험치 대본 상한 20/50/80을 유지한다.

## 후반 보급 거점

| 지역 | 보급 거점 | 보급대 기본 칸 | 귀환/빠른 이동 도착 칸 |
|---|---|---|---|
| 7막 유리 해안 | 유리등불 야영지 | (-7, 3) | (-7, 2) |
| 8막 뒤집힌 로비 | 막간 보급 대기실 | (-7, 3) | (-7, 2) |

북서쪽 보급대를 조사하거나 상점 메뉴를 열어 시약·정화·FP·기록 도구 8종을 구매한다.
상점에서 유료 휴식을 이용할 수 있다. 기본 요금은 기존 마을 상점과 같은 30금화다.
기존 아이템의 구매/판매 단가를 그대로 사용한다. 핵심 도구·이벤트 전용 도구는 보급하지 않는다.

해당 지역으로 이동하면 귀환 지점을 자동 설정한다. 월드맵은 실제 방문한 거점만 빠른 이동할 수 있으며
기존 이야기 입장 조건을 다시 확인한다. 기존 저장의 방문 기록도 인정한다.
이미 다른 후반 지역에 저장된 플레이어는 지도로 방문했던 거점에 돌아가 새 귀환 지점을 설정할 수 있다.

일곱 마을과 마을 복구/소문 정책은 그대로다. 두 지역은 필드 속 보급 거점으로 남으며 야생 조우와
지역 대표 그림자·기존 퀘스트·포털을 유지한다. 새 NPC나 그림자 재사용 NPC 이미지를 추가하지 않는다.
보급대는 환경 아트와 이름/서비스 안내판을 사용한다.

`JourneyHubCatalog`가 상품·위치를 정의하고 `JourneyHubPolicy`를 이동·상점·지도에서 공유한다.
`JourneyHubStation.Ensure`는 생성기와 기존 씬 로드에서 모두 호출한다. 지형을 적용하기 전에 배치하며
보급대·귀환 칸을 구조 카탈로그의 안전 좌표에도 포함했다(총 400곳).
기존 생성본에서 조사물이 같은 칸에 있으면 보급대는 가장 가까운 빈 칸으로 조정한다. 기존 조사물을 덮지 않는다.

## 도감·서고에서 찾기

- 각본집과 서고에 이름/칭호 검색, 11속성 필터, 기본/이름/레벨 높은순/레벨 낮은순을 제공한다.
- 복원 이름과 원래 이름으로 모두 찾는다. 여러 단어를 띄어 쓰면 모두 포함하는 그림자를 찾는다.
- 미발견 이름은 검색되지 않는다. 칭호·속성은 기록한 그림자만 검색/필터에 사용한다.
- 도감의 레벨 정렬은 보유한 대표 개체 기준이며, 미보유 항목은 뒤로 보낸다.
- 도감 번호·전체 수집 진행·이정표 보상 계산은 필터와 관계없이 전체 데이터 기준이다.
- 서고 필터/정렬은 표시 목록만 바꾼다. 출전 파티 여섯 칸과 저장된 개체 순서는 바꾸지 않는다.
  필터를 바꾸면 진행 중 교체 선택을 해제해 숨은 개체를 잘못 교체하는 상황을 막는다.
- `초기화`는 검색/속성/정렬을 기본값으로 돌린다. 도감의 전체/조우/기록 상태 필터는 별도다.
- 검색 중 `X`/`Tab`이 각본집을 닫지 않도록 입력 필드 포커스를 확인한다.

검색 조건은 현재 실행 중 UI 설정이며 저장 스키마에 추가하지 않는다.
`CollectionQuery`는 복사한 표시 목록만 정렬하고 원본 파티/서고 리스트를 수정하지 않는다.

## 가방·상점 분류와 수량 거래

전체/HP 회복/상태 정화/FP 회복/각본 기록/경험치/핵심 도구 분류와 이름 검색을 제공한다.
회복+정화 복합 도구는 두 분류에서 모두 찾을 수 있다. 빈 결과도 안내한다.

상점의 구매/판매 버튼은 수량 확인 창을 연다. 직접 수량을 입력하거나 x1/x5/x10/최대를 고르고,
보유 수량·금화·단가·총액을 확인해 `거래 확정`을 누른다. 미리보기와 취소는 금화/도구를 바꾸지 않는다.
뒤로 가기는 확인 창부터 닫고 상점은 유지한다.

최대 수량은 보유 금화, 재고, 금화/스택 정수 상한을 함께 고려한다. 확정 시 최신 상태로 다시 판정한다.
부족한 금화/재고, 0/음수/잘못된 수량, 정수 상한 초과는 전체 거래를 거부한다.
핵심 도구는 한 개만 살 수 있고 팔 수 없다. 단가를 할인하거나 경험치 도구의 사용 한도를 바꾸지 않는다.

`ItemTradePolicy`가 넓은 정수 연산으로 총액과 결과를 계산한다. SaveManager는 검증 후 수량/금화를
한 번에 반영하고 변경 이벤트를 각 한 번 보낸다. 기존 단품 API는 수량 1로 연결된다.
성공한 확인 거래는 기존 방식대로 한 번 저장하며 마을 복구 활동도 확인 거래당 한 번 처리한다.
저장이 실패하면 현재 게임 상태를 유지하고 실패 안내를 표시한다. 실제 저장 I/O는 이 환경에서 미검증이다.

## 검증

```sh
python Tools/check-convenience.py
dotnet run --project Tools/ConvenienceChecks/ConvenienceChecks.csproj
python Tools/check-adventure-content.py
dotnet run --project Tools/AdventureChecks/AdventureChecks.csproj
```

- 실제 거점/지역/검색/아이템 분류/거래 정책의 .NET 검사 **7,021개** 통과.
  2개 거점, 기존 21개 도구, 방문·이야기 조건, 비공개 검색, 원본 순서 보존,
  일괄 거래의 정확한 합계·정수 경계·최대 수량을 확인했다.
  Unity 리소스/씬/저장/ScriptableObject는 관리 코드 대역이며 실제 UI/물리/파일 I/O 검사가 아니다.
- 기존 진화/지형 정책 **31,771개**, 퀘스트 **262개**, 대본/수동 입력/아이템 연결 검사 통과.
- 기존 Unity 참조 DLL과 호환 표면을 이용한 런타임 C# 소스 컴파일 및 데스크톱 조건부 컴파일 통과.
  Unity 2022.3 에디터 컴파일을 대신하지 않는다.
- 카탈로그 재생성 동일 결과, 신규 C# 구문/메타데이터/데이터·UI 연결 정적 검사 통과.
- `ConvenienceRegression`을 Unity 감사에 연결하고 `ReleasePlayModeQa`에 실제 일괄 거래 보존 검사를 추가했다(미실행).

Unity 2022.3.52f3가 없어 에디터 컴파일·씬 생성·Play Mode·실제 저장/귀환·UI·기기 성능은 확인하지 못했다.
APK/AAB를 만들지 않았다. 별도 검증 복사본에서 다음을 확인해야 한다.

1. 두 거점 첫 도착→자동 귀환 지점, 후반 전투 패배→거점 복귀, 기존 방문 저장→지도 빠른 이동
2. 보급대 접근/조사/유료 휴식, 보급 물품 8종, 지형·포털·야생 조우 유지
3. 도감 번호·이정표 진행 유지, 복원 이름/무속성/미발견 검색, 서고 정렬 후 실제 파티 순서 유지
4. PC 한글/영문 입력·모바일 키보드·드롭다운·빈 결과·교체 취소·뒤로 가기·입력 잠금
5. 일괄 구매/판매/최대/취소·잔액 변동 후 재확인·저장 실패/재시작·기존 단품 API
