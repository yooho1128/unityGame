# 180종 그림자 전용 이미지

작업 전에는 실제 게임 180종의 데이터와 표시용 참조가 있었지만, 전용 초상은 21종이었다. 나머지 159종은 생성 실루엣이나 공용 배역을 사용했다. 기존 21종을 보존하고 실제 게임에서 빠진 159종의 기본 이미지를 제작한다. 최초 로컬 생성 폴더 명단은 현재 월드 명단과 32종이 달랐으므로, 두 명단의 합집합 212종에 대해 이미지를 보존·제작하고 실제 게임의 180종을 별도로 검사한다. 구 명단에만 있는 32종은 예비 아트로 명시하며 실제 게임 완성 수에 포함하지 않는다.

## 제작 및 연결

- 종별 데이터의 이름·칭호·설정을 바탕으로 내장 `image_gen` 도구를 사용했다. 최종 프롬프트·종별 ID·원본 경로는 `ShadowPortraitPrompts` 폴더에 저장했다.
- 잿빛 사제, 종탑 기사, 검은 시험관, 붉은 뿔의 추격자, 책 먹는 용은 개별 PNG다. 시트 12장에는 실제 게임의 나머지 154종과 예비 32종이 들어간다. 각 칸을 독립적인 종별 ID로 임포트하며, Roster10의 사용하지 않는 6칸은 연결하지 않는다.
- 결과는 개별 PNG 26장과 시트 12장에 담긴 고유 스프라이트 212개다. 실제 게임에 사용하는 것은 180개다. 파일 수나 예비 종을 게임 내 종수로 계산하지 않고 같은 영역을 여러 종에 공유하지 않는다.
- 전투 초상·각본집·파티 UI와 필드에 동일 종의 전용 아트를 연결한다. 필드는 한 칸 크기로 정규화하고 기존 걷기·부유·날갯짓 모션을 적용한다. 이번 제작물은 종별 기본 이미지이며 별도 다중 프레임 애니메이션 세트는 아니다.
- Android는 알파가 있는 ETC2 RGBA8, Point 필터, 밉맵 없음으로 설정한다. 시트는 전체 해상도를 유지해 각 종이 192px 이상이 되도록 검사한다.
- 새 `ShadowArtRoster` 리소스가 ID와 Sprite를 연결한다. 실행 시 시각 필드만 갱신하므로 기존 로컬 생성 데이터·씬과 세이브를 덮어쓰지 않는다. 이전 씬에 남아 있던 공용 필드 프레임도 조우 심볼·보스 초기화 때 전용 이미지로 갱신한다.
- 검증 프로젝트에서는 전체 월드를 재생성해 새 이미지 참조가 직렬화된 APK를 만든다. 원본 프로젝트의 기존 미추적 생성 파일은 보존한다.

## 검증

`ShadowRosterArtBatch.GenerateCheckAndBuildForCi`에서 다음을 확인한다.

- 데이터 180종 모두 전용 전투/각본집 Sprite와 일치
- 필드 180종 모두 자기 종의 전용 Sprite와 일치
- 180개 이미지 영역이 모두 서로 다르며, 누락·잘못된 ID 없음
- 시트 칸의 유효 알파·비어 있지 않은 그림·해상도·Android 압축 설정
- 180종의 필드 크기 상한과 기존 맵/충돌 회귀 검사
- 전체 게임 회귀 검사와 폴드·20:9·16:9 UI 검사, Android APK 빌드

종별 연결·파일·Sprite 이름·크기는 `Generated/ShadowRoster/ROSTER_ART.json`에 기록한다.
