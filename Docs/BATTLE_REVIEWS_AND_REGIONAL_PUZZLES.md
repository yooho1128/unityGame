# 전투 복기와 지역 장치

## 전투 복기

필드 메뉴의 **전투 복기**에서 현재 저장 슬롯의 최근 20전을 확인한다.
승리·패배·기록·도주, 지역·전투 종류·턴·기절 횟수, 당시 전체 파티/적의 이름·단계·레벨·시작 능력치와
전후 HP, 실제 받은 피해·회복량·회복 기술 사용 횟수, 개체별 실제 XP 증가량과 소비 도구를 표시한다.
패배 후 파티가 자동 회복되기 **전**에 전투 HP를 확정한다. 시작 능력치에는 동행 패시브를 포함한다.
지역 난이도의 별도 피해 배율은 이 능력치에 합산하지 않으며 지역·전투 종류·빌드에 맞는 `EncounterDifficultyPolicy`로 조회해야 한다.

- 회복량은 `BattleUnit.Heal`의 실제 적용분만 누적한다. 최대 HP를 넘긴 회복은 제외하고 기술/도구/보스 페이즈를 포함한다.
  레벨업에서 직접 적용한 회복은 제외한다. 피해량은 실제 HP 감소분이며 상태 피해도 포함한다.
- 경험치는 실제 성장 함수 `ShadowInstance.ExperienceToNext`의 누적 XP 차이다. 전투 경험치 합계는 전원 지급분의 합이며 단일 개체의 획득량이 아니다.
- 전투 보상 금화와 결과 반영 전후의 실제 금화를 별도로 표시한다. 후자에는 같은 결과에서 발동한 퀘스트 보상이 포함될 수 있다.
  상점 지출·향후 휴식비를 측정하는 경제 장부는 아니다.
- 성공적으로 시작한 전투만 미완료 스냅샷을 저장한다. 결과 반영 후 같은 ID를 완료 기록으로 교체한다.
  새 실행에서 발견한 이전 실행의 미완료 기록은 `Interrupted`로 표시하고 승패 분석에서 제외한다.
  결과 화면 확인 전 종료한 전투도 미완료로 남을 수 있다.

기록은 `Application.persistentDataPath/BattleReviews/<saveGuid>.json`에 로컬 저장한다.
게임 저장 v14를 변경하지 않고 슬롯 GUID로 분리한다. 전투 복기 `version: 1`은 기기 QA JSON v2와 별도 형식이다.
복사 버튼은 현재 슬롯의 JSON을 클립보드에 복사하며 자동 업로드는 없다.
`.tmp` 작성→정상 주 파일 `.bak` 보존→교체 순서이고 손상 주 파일은 다음 기록 시 `.invalid_*`로 보존한다.
읽기 시 정상 주 파일→임시→백업 순서로 복구한다. 저장 오류는 화면에 알리고 게임 진행을 막지 않는다.
파일 쓰기 실패 때 메모리의 기록은 유지되며 이후 새 기록 저장 시 다시 포함된다. 중복 완료 요청 자체가 디스크 재시도를 하지는 않는다.
최신 20전만 보관하므로 대표성 있는 전수 측정이나 게임 진행 복구 수단으로 취급하지 않는다.

선택해서 복사한 기록을 분석하려면:

```sh
python Tools/summarize-battle-reviews.py /path/to/review.json > review-summary.json
```

같은 지역/전투/게임 버전/빌드 GUID 단위로 표본 수, 결과별 횟수, 평균 턴/인원/레벨/회복/소비/실제 XP/금화를 출력한다.
잘못된 형식·다른 슬롯의 행·중복 파일은 오류로 끝내고 진행 중/중단은 별도 집계한다. 자동 밸런스 판정·수정은 하지 않는다.
이 작업에서 실제 플레이 기록을 수집하거나 밸런스 검증을 완료하지 않았다.

## 지역 전용 퍼즐 3종

| 지역 | 장치 | 단서와 방식 | 해금 |
| --- | --- | --- | --- |
| 금단의 서가 | 흩어진 목차 복원 | 파란→황금→붉은 갈피 순서. 오입력 뒤 맞는 시작 부분을 보존 | 서고 양쪽 책장 지름길 |
| 태엽 골목 | 태엽의 세 등불 | 왼 태엽 ①②/가운데 ①②③/오른 ②③ 반전. ①③만 켜기 | 공방 양쪽 정비 지름길 |
| 유리 해안 | 해안의 세 반사경 | 조사할 때 북→동→남→서. 부두 동쪽/달 서쪽/파도 남쪽 맞추기 | 해안 양쪽 판자길 지름길 |

단서판에 조작 방법과 목표를 모두 적었다. 장치 이름표와 알림에서 현재 상태를 확인한다.
남서쪽/남동쪽 지름길 표식을 바라보고 조사하면 같은 지역의 반대편으로 이동한다.
서가의 순서와 등불의 토글, 반사경의 회전은 서로 다른 규칙이다. 모든 도달 가능한 미완료 상태에서 해결할 수 있다.
필수 진행 조건·보스·NPC 대화·기존 이동 권능을 우회하지 않고 금화/경험치/아이템 보상을 지급하지 않는다.

완료는 기존 저장 플래그 `regional_puzzle_<id>_complete`에 슬롯별로 저장한다.
부분 조작은 해당 씬에 머무는 동안 유지되고 씬을 다시 불러오면 초기화된다. 완료 후에는 초기화되지 않는다.
완료 상태는 탐험 수첩/방문한 지역의 월드맵 상세에도 표시한다. 기존 일반 레버·비밀길과 별도 항목이다.
새 씬 생성과 기존 씬 런타임 양쪽에 배치하며 중복 생성을 방지한다.
제작 좌표 18곳을 추가해 전체 안전 좌표 418곳을 보호한다. 기존 조사물과 겹치면 가까운 빈 칸에 놓고 실제 배치도 지형의 안전 좌표로 반영한다.
지름길 목적지는 트리거이고 이동 전 안전 칸 확인·입력 잠금·페이드·위치 저장을 사용한다.
그림자 이미지를 전용 장치 그래픽으로 사용하지 않으며 현재는 기존 지형 스프라이트와 이름표로 표현한다. 전용 장치 아트는 후속이다.
웹 도감은 같은 카탈로그에서 초기 위치와 해법을 가져오며 해법은 기본으로 접어 둔다.

## 검증

- 신규 .NET 237개: 실제 정책/파일 서비스와 세 퍼즐의 전체 도달 상태 검사. 순서 겹침, 저장 완료 복구/중복,
  슬롯 분리, 원본 스냅샷 불변, 최근 20전 제한, 손상 파일 백업 복구/격리, 세션 중단, I/O 실패 격리.
- 합성 JSON 분석 12개: 6대1 표본, 실제 XP/금화 구분, 미완료 제외, 형식/중복/음수/HP 오류 거부. 합성 표본은 플레이 결과가 아니다.
- 기존 진화·지형 31,951개/편의 7,021개/퀘스트 262개/경험치 구간 26개 통과.
- C# 참조 DLL/호환 표면을 사용한 런타임 및 PC 입력 분기 소스 컴파일 통과.
  실제 Unity 버전의 임포트/컴파일 확인을 대체하지 않는다. 변경 C# 구문, 데이터/연결/결과 반영 순서 정적 검사도 수행.
- Unity 전체 검사에 `ReviewPuzzleRegression`을 연결했다. Unity가 없어 이 네이티브 검사 실행은 미완료다.

```sh
dotnet run --project Tools/ReviewPuzzleChecks/ReviewPuzzleChecks.csproj
python Tools/test-battle-review-summary.py
python Tools/check-review-puzzles.py
```

Unity 2022.3.52f3 별도 검증 복사본에서 씬 생성·컴파일·Play Mode를 확인해야 한다.
기존 저장에서 3지역 진입, 이름표/단서/물리 조사, 모든 오입력 후 해결, 완료 저장·씬 재진입·슬롯 교체,
지름길 양방향 이동·중단 시 입력 해제, 메뉴 스크롤/뒤로가기/클립보드,
승패/포획/도주별 실제 회복·레벨업·보상 수치와 파일을 대조하는 수동 검증이 남아 있다.
모바일 UI 가독성·동기 파일 I/O 지연·네이티브 JsonUtility 직렬화도 실기기로 확인해야 한다.
